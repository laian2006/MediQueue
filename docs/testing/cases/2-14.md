# Kiểm thử hủy và theo dõi phiếu 2.14

Đã chạy trên Chrome 157 ở chiều rộng 360 px, Node.js 24.22.2 và PostgreSQL
18.6. Client dùng nhánh `task/2.14` dựa trên 1.14 tại `50e6a58`, server dùng
nhánh `task/2.13` từ `main` tại `fbbcf79`. Build và 7 test client đạt. Cả 4 ca
hồi quy `patient-flow.spec.js` và luồng mới `patient-cancel.spec.js` đều đạt.

- Hủy phiếu số 1 qua nút **Hủy phiếu**. API trả 200, giao diện hiện **Đã hủy**
  và cho lấy số mới khi phiên còn mở. Màn hình đang theo dõi phiếu số 2 tự
  cập nhật số phiếu phía trước từ 1 về 0.
- Khi Chrome mất kết nối, giao diện giữ số phiếu cùng giờ đồng bộ gần nhất và
  khóa nút hủy. Khi kết nối lại, thông báo dữ liệu cũ biến mất sau lần đọc thành công.
- Khi phiếu vừa chuyển sang `CALLED`, API hủy trả 409. Giao diện đọc lại,
  hiện **Đã được gọi** và ẩn nút hủy. Test đặt trạng thái `CALLED` bằng SQL
  trước khi gửi yêu cầu hủy thật vì API gọi lượt chưa ghép vào bản thử.
- Đổi hồ sơ ẩn phiếu cũ. `/patient-demo` vẫn đọc dữ liệu mô phỏng.
- Ca hồi quy mất phản hồi cấp số xác nhận lần gửi lại giữ nguyên cả ba trường
  trong yêu cầu và không tạo thêm phiếu. Cần xác minh lại với API phát lại phiếu
  theo `requestId` khi 2.7 lên `main`.

## Chạy lại

Chạy client và server theo [README](../../../README.md), với API hủy của 2.13
và CSDL thử mới chạy migration, seed và chưa mở phiên. Cài Playwright như mô tả
trong [ca 1.14](1-14.md). `MEDIQUEUE_E2E_DATABASE_URL` phải trỏ tới chính CSDL
thử của server vì ca thử cập nhật trạng thái một phiếu trong đó.

```powershell
$env:MEDIQUEUE_E2E_URL = 'http://localhost:5173'
$env:MEDIQUEUE_E2E_DATABASE_URL = 'postgresql://mediqueue_user:replace_me@localhost:5432/mediqueue_test'
node --test tests/e2e/patient-cancel.spec.js
```

Sau khi 2.13, 2.7 và luồng gọi/ghi vắng được tích hợp, chạy lại ca người bệnh
trên bản ghép và xác minh thay đổi trạng thái từ API nhân viên.
