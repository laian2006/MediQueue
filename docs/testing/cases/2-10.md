## Scope

Implement three staff-only queue operations:

| Endpoint | Transition | Event |
| --- | --- | --- |
| POST /api/v1/queue/tickets/{ticketId}/recall | CALLED -> CALLED | RECALLED |
| POST /api/v1/queue/tickets/{ticketId}/start | CALLED -> REGISTERING | STARTED |
| POST /api/v1/queue/tickets/{ticketId}/complete | REGISTERING -> COMPLETED | COMPLETED |

These endpoints accept no request body.

## Acceptance criteria

- Recall preserves the ticket ID and number.
- Recall updates lastCalledAt.
- Start and complete enforce the allowed source states.
- CALLED and REGISTERING occupy the counter.
- Completion releases the counter.
- Operations are allowed in OPEN and STOPPED sessions.
- CLOSED sessions are rejected.
- Authentication and staff authorization are required.
- Invalid UUIDs and missing tickets are rejected.
- Ticket updates and events use the same transaction.
- Audit failure rolls back both the ticket and event.
- Concurrent requests cannot produce conflicting transitions.
